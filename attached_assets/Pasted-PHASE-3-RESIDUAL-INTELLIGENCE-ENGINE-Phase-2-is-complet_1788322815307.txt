==================================================
CORE INNOVATION
==================================================

Traditional reconciliation often asks:

"Does this individual transaction match?"

Our system additionally asks:

"Has the population-level behavior of reconciliation residuals changed?"

For every evaluated control:

residual = actual_amount - expected_amount

The system must preserve residuals as structured observations.

A residual should not only contain an amount.

Create a ResidualObservation model containing at least:

residual_id
control_id
domain
entity_id
account_id
merchant_id
partner_id
timestamp
expected_amount
actual_amount
residual_amount
currency
status
metadata

Use Decimal for all monetary values.

==================================================
4. DISTRIBUTION SHIFT
==================================================

Implement methods to compare:

baseline residual distribution

against

current residual distribution.

The analyzer should calculate distribution-shift indicators.

Implement at least:

A. Kolmogorov-Smirnov statistic

B. Wasserstein distance

C. Population Stability Index (PSI)

The system should gracefully handle small or empty populations.

Do NOT automatically declare fraud.

These metrics indicate behavioral change, not fraud.

==================================================
5. TEMPORAL DRIFT
==================================================

Residual behavior can change over time.

Implement deterministic temporal analysis.

Support:

rolling mean
rolling absolute residual mean
rolling zero-residual ratio

Also implement at least one sequential change detector:

CUSUM

or

EWMA

Prefer CUSUM if implementation remains simple and deterministic.

The output should indicate whether the residual process appears stable or has experienced a change.
