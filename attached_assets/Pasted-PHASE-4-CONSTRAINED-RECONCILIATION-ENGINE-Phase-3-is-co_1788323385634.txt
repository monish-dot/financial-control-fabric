The purpose of this phase is to build a deterministic reconciliation optimizer for complex many-to-many settlement relationships.

==================================================
CORE OBJECTIVE
==================================================

Traditional matching often assumes:

one internal transaction
↔
one external transaction

This is insufficient for settlement systems.

Our engine must support:

many internal obligations
↔
many external settlement records

Examples:

3 internal obligations
→ 1 bank settlement

1 internal obligation
→ 3 partner confirmations

5 internal obligations
→ 2 bank settlements

The engine must determine the best valid allocation subject to financial constraints.

==================================================
4. CONSTRAINTS
==================================================

The optimizer must enforce:

CONSTRAINT 1:

For every internal item:

sum(allocated_amount)
<=
internal_amount

CONSTRAINT 2:

For every external item:

sum(allocated_amount)
<=
external_amount

CONSTRAINT 3:

Allocations cannot cross currencies.

CONSTRAINT 4:

Negative allocations are forbidden.

CONSTRAINT 5:

An allocation must satisfy configured matching constraints.

6. OPTIMIZATION OBJECTIVE
==================================================

Implement an optimizer using OR-Tools if practical.

Objective:

maximize total valid matched amount

while respecting constraints.

Secondary objective:

prefer stronger compatibility matches.

Conceptually:

maximize:

matched_amount
+
small_weight × compatibility_score

Do NOT allow compatibility score to override financial constraints.

Financial feasibility always comes first.

If OR-Tools cannot be used reliably in the current environment, implement a deterministic fallback optimizer and document the limitation.
